# 飞书动态任务进度条 (Feishu Dynamic Task Feedback)

> **让飞书 Agent 在执行长耗时任务时“保持安静，且进度可见”。用表情积木展示任务状态，彻底终结长任务的等待焦虑与文本刷屏。**

![Agent Skills](https://img.shields.io/badge/Skill-飞书专属-blue)
![Status](https://img.shields.io/badge/Status-稳定-success)

## 💡 你什么时候需要它？

1. **长时间等待焦虑**：Agent 执行复杂代码、爬取网页或调用外部大模型，需要几十秒甚至数分钟。不给反馈，用户以为卡死了；给反馈，文字刷屏太烦人。
2. **文本格式幻觉**：强迫症受不了 AI 在回复文本里夹杂 `[Thinking...]`、`[Done]` 这种机器感极强的占位符，且经常格式错乱。
3. **“偷看”思考过程**：希望随时能瞄一眼 Agent 当前到底进行到了哪一步（接收、思考、执行、完成），但不需要它用正文汇报。

## 🎯 它会交付什么？

本 Skill 会在飞书消息底部，像进度条一样依次点亮并追加表情（Reaction），过程丝滑、静默：

**(占位：此处后续可替换为展示无声进度条丝滑动画的 GIF 录屏 `assets/showcase.gif`)**

- 📥 收到指令：点亮 `Get`
- 🤔 解构思考：点亮 `THINKING`
- ⚙️ 全力执行：点亮 `STRIVE`
- ✅ 任务封包：点亮 `DONE`
- ❌ 执行遇阻：点亮 `SOB`

## 🚀 快速开始

将此 Skill 目录放置于您的工作区或加载到 Agent 的 `skills/` 目录中。
本技能配置为 `alwaysActive: true`，无需手动通过关键词触发，只要接管飞书聊天上下文，它就会自动充当护卫，拦截不合理的文本进度汇报并转换为表情气泡。

## 🗣️ 触发方式

只要发给 Agent 的是需要一定时间处理的任务，它就会默默启动进度追踪：
- *"帮我把这个 50 页的 PDF 总结成大纲。"*
- *"去 GitHub 帮我搜一下同类开源项目，然后整理成表格发出来。"*
- *"执行这段部署脚本，等全部跑完再回复我结果。"*

## ⚔️ 它和同类有什么不同？

| 特性 | 传统的 Agent 反馈 | Feishu Dynamic Task Feedback |
| :--- | :--- | :--- |
| **打扰程度** | 极高（每次状态改变都发一条新文本） | **极低**（静默在原有消息下挂载表情气泡） |
| **幻觉风险** | 经常伪造虚假的进度文本格式 | **零幻觉**（物理拦截与黑白名单双重锁定） |
| **网络抖动** | 容易卡死或报错中断 | **严密**（内置 Retry -> Fallback 降级恢复逻辑） |
| **时序错乱** | 并发调用导致乱序返回 | **串行锁定**（上一个表情点亮前，绝不执行下一步） |

## 🛡️ 安全边界

- **物理隔离**：本 Skill 在启动前会阻断所有旧记忆联想，确保 AI 只对“当前”指令做出表情反应。
- **不触碰正文**：严格禁止 AI 在回复正文中添加任何模仿进度条的标记，彻底根除“假装在执行”的幻觉。
- **不修改/删除信息**：本控制流为“只增不减”模式，通过顺序追加表明进度，绝不调用“撤回”或“删除”类高危 API。

## 🧪 验证与测试

建议使用 `test-prompts.json` 中的示例进行验证：

**测试指令**：
> "这是一个耗时测试：请在不发任何文本的情况下，依次经历思考和执行阶段，然后告诉我你完成了。"

**期望输出**：
1. Agent 立即在当前消息下点亮 `Get` 确认接收。
2. Agent 开始调用内部逻辑（可停顿几秒），点亮 `THINKING`。
3. Agent 开始干活，点亮 `STRIVE`。
4. 最终点亮 `DONE`，此时才发送一条包含确认信息的正文消息。
