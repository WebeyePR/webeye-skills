# WebEye 云服务知识库文档整理器

## 概述

将用户提供的原始材料（飞书文档链接、本地文件、文本内容、会议纪要等）重新组织为符合 WebEye 云服务知识库规范的结构化文档，并自动判断应归入的知识库板块。

## 知识库目录结构

WebEye 云服务知识库包含以下一级板块，整理时需判断文档归属：

| 板块 | 适用内容 |
|---|---|
| **入门指南** | 新用户上手、账号创建、基础概念介绍 |
| **解决方案** | 按行业/场景的完整解决方案（游戏、泛娱乐、电商等） |
| **最佳实践** | 经过验证的实操方法、配置建议、性能优化 |
| **操作指南** | 具体产品/功能的 step-by-step 操作步骤 |
| **MSP 服务清单** | 托管服务相关的服务内容、SLA、流程规范 |
| **客户案例** | 真实客户落地案例、成效数据 |
| **FAQ** | 常见问题与解答 |

如果内容无法明确归入以上板块，标记为「待分类」并说明建议归属。

## 知识库文档标准格式

每篇整理后的文档必须包含以下结构：

```markdown
# {文档标题}

> **摘要**：{1-2 句话概括文档核心内容，不超过 80 字}

## 适用场景
{说明本文档适用于什么情况、什么用户}

## 前置条件
{使用本文档前需要准备什么：账号权限、已开通服务、环境要求等；无则写"无"}

## 正文
{按逻辑分节组织内容，使用二级/三级标题}

### 步骤一 / 概念一
{具体内容}

### 步骤二 / 概念二
{具体内容}

## 注意事项
{重要提醒、限制、常见坑}

## 相关文档
{链接到知识库内其他相关文档；无则写"暂无"}
```

### 格式规范

- 标题层级：一级标题仅用于文档标题，正文从二级标题开始
- 操作步骤类内容使用有序列表，概念说明使用无序列表
- 代码/命令使用代码块标注语言
- 关键参数、产品名使用**加粗**
- 涉及外部链接使用标准 Markdown 链接格式
- 文档末尾不保留原始来源的无关信息（如聊天记录、时间戳、@人等）

## 工作流程

### 第一步：获取并读取原始内容

根据用户提供的输入类型处理：

- **飞书文档链接**：使用 lark-doc 读取文档全文
- **本地文件**：使用 Read 工具读取（支持 .md / .txt / .pdf / .docx）
- **直接粘贴的文本**：直接使用
- **多个文档**：逐个读取后判断是否合并为一篇或拆分为多篇

### 第二步：内容理解与分类

1. 提炼文档核心主题
2. 对照「知识库目录结构」判断归属板块
3. 识别内容类型：操作指南 / 概念说明 / 解决方案 / 案例 / FAQ
4. 如果用户明确指定了板块，以用户指定为准

### 第三步：按标准格式重组

1. 撰写摘要（1-2 句，不超过 80 字）
2. 补充适用场景和前置条件（原文没有则根据内容推断，标注为「整理者补充」）
3. 将正文按逻辑重新分节，使用二级/三级标题
4. 清理无关内容（闲聊、时间戳、重复信息）
5. 统一术语和格式
6. 补充注意事项和相关文档链接

### 第四步：输出与交付

1. 输出完整的整理后文档（Markdown 格式）
2. 在文档开头标注：
   - 建议归属板块
   - 原始来源（链接或文件名）
   - 整理时间
3. 询问用户是否需要直接创建到知识库对应目录（使用 lark-doc / lark-wiki 创建）

## 质量检查清单

输出前逐项确认：

- [ ] 摘要不超过 80 字，准确概括核心内容
- [ ] 适用场景和前置条件已填写（无则明确写"无"）
- [ ] 正文结构清晰，标题层级正确（正文从二级开始）
- [ ] 操作步骤使用有序列表，概念使用无序列表
- [ ] 无原始聊天痕迹（@人、时间戳、表情符号）
- [ ] 术语统一，产品名/参数名加粗
- [ ] 代码块标注了语言
- [ ] 注意事项已提炼
- [ ] 建议归属板块已标注
- [ ] 相关文档链接已补充（无则写"暂无"）

## 特殊情况处理

- **内容过短（< 200 字）**：判断是否适合作为 FAQ 条目，或建议与其他文档合并
- **内容过长（> 5000 字）**：考虑拆分为多篇文档，或在文档内建立清晰的目录结构
- **混合主题**：询问用户是否拆分，或按主要主题整理并在相关文档中提及其他主题
- **涉密/敏感内容**：提醒用户确认是否适合放入可对外分享的知识库
