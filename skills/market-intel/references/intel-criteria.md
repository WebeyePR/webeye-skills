# 行业情报判断准则（intel）

对 `out/latest.json` 变更集逐条判断。四问结构沿用 change-watch 的 criteria，口味换成市场情报。

## 一、四条必答问题

1. **是值得看的行业情报吗？** 不是（站点噪声、活动邀约、纯营销、与行业无关）→
   `"discard": true` + `discard_reason`。**什么都不写 = 漏判**，会被待判队列反复带回，
   超过 24 小时进 `log/unjudged.jsonl`。
   **"判不出来" ≠ "判为无关"**：材料不足写 `significance: "unknown"`，落盘但不通知。
2. **什么类型？** 两到六个汉字短语，可复用。参考表：

   | 类型 | 含义 |
   |---|---|
   | `融资事件` | 企业完成新一轮融资（同时给 facts 抽一条事实） |
   | `产品发布` | 行业内公司发布新产品/新版本 |
   | `人事变动` | 高管更替、关键人才流动 |
   | `并购合作` | 并购、战略投资、生态合作 |
   | `政策监管` | 影响行业的政策、监管、合规动态 |
   | `行业趋势` | 有数据支撑的趋势、报告结论 |
   | `其他` | 自拟更准确的名字 |

3. **多重要？** `high`：大额/头部企业融资、行业级政策、代际性产品；`normal`：常规融资与产品动态；
   `low`：边缘动态；`unknown`：判不出来（不通知）。
4. **要不要通知？** `notify: true/false` + 一句 `notify_reason`。

## 二、事实抽取（与 intel 判断同时做）

条目里若出现**企业事实**（融资、招聘、归属行业），在 `facts` 数组里加一条（契约见
`references/lead-criteria.md`），并把该条 `change_id` 写进 `facts[].change_ids`——
这就是这条变更的"结论"，覆盖度校验同样认可。

同一事件多家报道：合并成一条 intel，`merged_change_ids` 列出被合并的 change_id，
`sources` 列全并给中文名，只通知一次。

## 三、防假条款（命中任一即 discard）

- 纯营销稿 / 品牌宣传，没有可验证事实；
- 传闻、二手转述，无原始出处；
- 活动邀约、课程推广、招聘平台自己的软文；
- 与 AI/电商/游戏行业无关的一般性内容；
- 同一事件的重复报道（引用已记录条目的 change_id）。

## 四、时间与溯源口径（沿用 change-watch）

- 各源时间戳不可跨源比较；判断"新不新"以本技能采集时刻为准；
- `title`/`summary` 里的公司名、数字必须能在该变更原文里找到——脚本会做数字核对，
  对不上标 `grounding: "unverified"` 并点名，看到就回原文改；
- **数字核对是三层判定**（实测教训：`$30B` 写成"300亿美元"曾被误拦）：
  ① 直引原文数字 → 通过；② 常见单位/汇率换算（×10 亿↔B、÷10000 万、×7.2 汇率等）
  → 脚本自动兜底通过，备注留档；③ 兜底认不出的 → 在 `number_notes` 里申报
  `{"数字": "换算依据"}` 后通过，同样留档。申报必须属实，留档供人工审计；
- `url` 必须能点开原文；拿不到就说明依据不足，判 `unknown`。
